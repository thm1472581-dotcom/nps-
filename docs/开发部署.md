# NPS 开发与部署

本文档说明本仓库（修改版 `nps2` / `npc2`）的开发环境、编译打包、服务端/客户端部署与常用运维操作。当前版本：**0.26.0**。

---

## 1. 环境要求

| 项目 | 要求 |
|------|------|
| Go | 建议 **1.15+**（`go.mod` 声明 1.15；本机可用更高版本） |
| 操作系统 | Windows / Linux / macOS（darwin）均可开发与交叉编译 |
| 网络 | 拉取依赖建议配置 Go 代理（国内环境） |
| 可选 | OpenSSL（生成自签证书）、UPX（压缩体积，非必须） |

```bash
# 查看 Go 版本
go version

# 可选：设置模块代理
go env -w GOPROXY=https://goproxy.cn,direct
go env -w GO111MODULE=on
```

项目根目录：

```text
A:\001-project\033-nps
```

## 3. 本地编译

### 3.1 推荐：一键编译脚本（Windows）

```cmd
cd A:\001-project\033-nps
scripts\build_all.bat
```

默认行为：

- 编译修改版服务端 `nps2.exe`、客户端 `npc2.exe`（当前 Windows amd64）
- 同步交叉编译常用 Linux amd64 产物
- 输出到 `dist\` 目录，并复制运行所需的 `conf`、`web` 资源

可通过参数控制目标平台，详见 `scripts\build_all.bat` 内说明。

### 3.2 手动编译（修改版）

在项目根目录：

```cmd
:: Windows 本机
set CGO_ENABLED=0
go build -ldflags "-s -w" -o dist\nps2.exe .\cmd\nps2
go build -ldflags "-s -w" -o dist\npc2.exe .\cmd\npc2
```

```bash
# Linux / macOS
export CGO_ENABLED=0
go build -ldflags "-s -w" -o dist/nps2 ./cmd/nps2
go build -ldflags "-s -w" -o dist/npc2 ./cmd/npc2
```

### 3.3 交叉编译示例

```cmd
:: Linux amd64 服务端/客户端
set CGO_ENABLED=0
set GOOS=linux
set GOARCH=amd64
go build -ldflags "-s -w" -o dist\linux_amd64\nps2 .\cmd\nps2
go build -ldflags "-s -w" -o dist\linux_amd64\npc2 .\cmd\npc2
```

仓库内 `build2.sh` 提供多平台打包（linux/windows/darwin × amd64/arm64 等），在 Git Bash / WSL / Linux 下可直接执行。

### 3.4 原版入口（可选）

```bash
go build -o nps ./cmd/nps
go build -o npc ./cmd/npc
```

日常请优先使用 `nps2` / `npc2`。

## 4. 服务端部署

### 4.1 运行目录准备

服务端除可执行文件外，还需要：

```text
nps2(.exe)
conf/nps.conf
conf/server.pem
conf/server.key
web/views/
web/static/
```

可直接使用 `scripts\build_all.bat` 生成的 `dist\windows_amd64_server\`（或对应平台目录）。

### 4.2 关键配置（`conf/nps.conf`）

至少确认并修改：

| 配置项 | 默认 | 说明 |
|--------|------|------|
| `web_port` | 8080 | Web 管理端口 |
| `web_username` / `web_password` | admin / 123 | **务必修改默认密码** |
| `bridge_port` | 8024 | 客户端连接端口 |
| `bridge_type` | tcp | 与客户端通信方式（tcp / kcp） |
| `http_proxy_port` / `https_proxy_port` | 80 / 443 | 域名代理监听端口 |
| `public_vkey` | 123 | 配置文件模式客户端公钥 |

生产环境建议关闭开发态多余日志，按需开启流量限制、端口白名单、IP 限制等。

### 4.3 安装为系统服务

**Windows（管理员 CMD）：**

```cmd
cd 解压目录
nps2.exe install
nps2.exe start
:: 其他：stop / restart / uninstall
```

安装后配置与数据通常位于 `C:\Program Files\nps`。

**Linux / macOS：**

```bash
sudo ./nps2 install
sudo nps2 start
# stop / restart / uninstall 同理
```

配置目录一般为 `/etc/nps`，日志常见于 `/var/log/nps.log`。

### 4.4 前台调试运行

```cmd
nps2.exe
```

便于查看控制台日志，确认端口监听与配置加载是否正常。

### 4.5 防火墙

至少放行：

- Web 管理端口（默认 8080）
- Bridge 端口（默认 8024）
- 实际开放的隧道端口、HTTP/HTTPS 代理端口（80/443 等）
- 若使用 KCP / P2P，按配置额外放行对应 UDP 端口

### 4.6 登录与创建客户端

1. 浏览器访问 `http://公网IP:8080`
2. 使用配置的账号密码登录
3. 「客户端」→「新增」，记下生成的 **vkey**

## 5. 客户端部署

### 5.1 无配置文件模式（推荐）

```bash
# 修改版参数
./npc2 --server 公网IP:8024 --vkey 客户端密钥
# 短参数
./npc2 -s 公网IP:8024 -k 客户端密钥
```

Windows：

```cmd
npc2.exe --server 公网IP:8024 --vkey 客户端密钥
```

连接成功后，Web「客户端」列表状态应为「在线」。随后在 Web 中配置 TCP/UDP/域名等隧道即可。

### 5.2 单文件固化参数（修改版）

```bash
echo 'CMDLINE: --server 公网IP:8024 --vkey 你的密钥' >> npc2
./npc2
```

或使用加密参数：

```bash
./npc2 --encryptcmd "--server 公网IP:8024 --vkey 你的密钥"
# 将输出写入文件尾部
echo 'CRYPTCMD: <加密串>' >> npc2
./npc2
```

之后可将该二进制拷贝到同环境其他机器直接运行（注意隧道目标地址语义：若目标为 `127.0.0.1`，则指向各自本机）。

### 5.3 配置文件模式

```bash
./npc2 --config conf/npc.conf
```

`npc.conf` 中配置 `[common]` 与各隧道段（tcp/udp/socks5/域名等）。示例见仓库 `conf/npc.conf` 与 `docs/use.md`。

### 5.4 注册为系统服务

```bash
# Linux
sudo ./npc2 install --server 公网IP:8024 --vkey 密钥
sudo npc2 start

# Windows（管理员 CMD）
npc2.exe install --server 公网IP:8024 --vkey 密钥
npc2.exe start
```

更换参数需先 `uninstall` 再重新 `install`。

### 5.5 连通性检查

- 从客户端机器探测服务端 `bridge_port` 是否可达（telnet / nc / Test-NetConnection）
- 确认 vkey 正确、服务端与客户端版本一致
- 查看客户端日志与 Web 在线状态

## 6. 常见部署流程示例（TCP 穿透）

目标：公网 `IP:13306` → 内网 MySQL `127.0.0.1:3306`

1. 公网机部署 `nps2`，改掉 Web 密码，放行 8080、8024、13306
2. Web 创建客户端，记录 vkey
3. 内网机运行：`npc2 -s 公网IP:8024 -k vkey`
4. Web → TCP 隧道 → 新增：服务器端口 `13306`，目标 `127.0.0.1:3306`
5. 外网测试：`mysql -h 公网IP -P 13306 -u ... -p`

更多场景（域名、Socks5、UDP、P2P）见 `docs/example.md`。

## 8. 开发说明

### 8.1 主要代码位置

| 路径 | 职责 |
|------|------|
| `cmd/nps2`、`cmd/npc2` | 修改版 CLI 入口、参数加密、文件尾部参数 |
| `server/` | 服务端代理实现（tcp/udp/http/socks5/p2p 等） |
| `client/` | 客户端连接、本地转发、健康检查 |
| `bridge/` | 桥接与会话管理 |
| `web/` | Beego Web 管理 |
| `lib/` | 公共能力（crypt、conn、config、rate、file 等） |

### 8.2 本地调试建议

1. 复制 `conf/` 到运行目录，按需改 `web_port` / `bridge_port` 避免冲突
2. 前台启动服务端：`go run ./cmd/nps2`
3. 另开终端启动客户端：`go run ./cmd/npc2 -s 127.0.0.1:8024 -k <vkey>`
4. 浏览器打开本地 Web 管理验证

### 8.3 测试与代码检查

```bash
# Makefile 中提供
make test
make build   # 注意：默认构建原版 cmd/nps、cmd/npc
```

修改版请直接 `go build ./cmd/nps2`、`./cmd/npc2` 或使用 `scripts\build_all.bat` / `build2.sh`。

### 8.4 版本号

版本定义于 `lib/version/version.go`。发版时请同步服务端与客户端版本，避免不兼容。

## 9. 故障排查速查

| 现象 | 排查方向 |
|------|----------|
| 客户端无法上线 | 网络/防火墙、`bridge_port`、vkey、版本是否一致 |
| Web 打不开 | `web_port`、本机监听地址、反向代理路径 `web_base_url` |
| 隧道不通 | 目标地址是否写对（`127.0.0.1` vs 内网 IP）、端口占用、白名单 |
| 服务装不上 | 是否管理员/root、旧服务是否未卸载 |
| 单文件无参数启动失败 | 是否使用 `>>` 追加、`CMDLINE:` / `CRYPTCMD:` 前缀是否正确 |

## 11. 安全建议（上线前必做）

1. 修改默认 Web 账号密码与 `public_vkey`
2. 按需开启 `allow_ports`、`ip_limit`、流量/连接限制
3. 高危端口优先使用私密代理或仅对可信 IP 开放
4. 生产环境关闭过高日志级别，定期备份 `conf` 与数据文件
5. 分发客户端时优先使用 `--encryptcmd` / `CRYPTCMD`，避免明文密钥泄露
