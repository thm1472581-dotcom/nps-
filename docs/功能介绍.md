# NPS 功能介绍

本文档介绍本仓库（NPS 修改版）的定位、核心能力与二次开发特性。当前版本：**0.26.0**。

---

## 1. 项目概述

NPS 是一款轻量级、跨平台的内网穿透代理服务器，采用 **服务端（nps）+ 客户端（npc）** 架构：

| 组件 | 入口目录 | 说明 |
|------|----------|------|
| 服务端 | `cmd/nps`（原版）、`cmd/nps2`（修改版） | 部署在公网机器，提供 Web 管理与隧道入口 |
| 客户端 | `cmd/npc`（原版）、`cmd/npc2`（修改版） | 部署在内网机器，主动连接服务端并转发流量 |

本仓库在官方 ehang-io/nps 基础上提供修改版入口（`nps2` / `npc2`），重点增强命令行参数形态与单文件分发能力。日常开发与部署请优先使用修改版。

**典型场景：** 将内网 SSH、数据库、Web 站点、RDP 等服务安全暴露到公网，或通过 Socks5/HTTP 代理访问内网资源。

---

## 2. 架构说明

```
外网用户 ──► 公网服务器(nps2) ──隧道──► 内网机器(npc2) ──► 内网目标服务
                 │
                 └── Web 管理界面（默认 :8080）
```

- 客户端主动连接服务端 `bridge_port`（默认 **8024**），无需在内网做端口映射。
- 隧道、域名、客户端等配置可在 Web 管理界面完成，多数改动热更新，无需重启。
- 客户端与服务端核心版本须一致，否则无法连接。

---

## 3. 代理与隧道模式

| 模式 | 用途举例 |
|------|----------|
| **TCP 隧道** | SSH、MySQL、RDP、任意 TCP 服务端口映射 |
| **UDP 隧道** | DNS、游戏、音视频等 UDP 场景 |
| **HTTP/HTTPS 域名代理** | 将内网站点通过公网域名反向代理出去 |
| **Socks5 代理** | 外网环境像 VPN 一样访问整个内网 |
| **HTTP 正向代理** | 外网通过 HTTP 代理访问内网站点 |
| **私密代理（secret）** | 访问时需额外密码，适合高敏感端口 |
| **P2P 代理** | 打洞直连，降低服务端中转压力（需配置 p2p 相关端口） |
| **文件访问（file）** | 将本地目录以 HTTP 方式对外提供（仅配置文件模式） |

### 域名代理扩展能力

- 静态文件缓存（`http_cache`）
- Host 修改、自定义 Header
- Http Basic Auth 站点保护
- 泛域名解析（如 `*.proxy.com`）
- 按 URL 路径路由到不同内网目标
- 多目标负载均衡（轮询）
- 自定义 404 页面

## 4. 安全与传输特性

| 能力 | 说明 |
|------|------|
| 加密传输 | 服务端与客户端通信可加密；支持 TLS（启动时随机证书） |
| Snappy 压缩 | 节省隧道流量、提升传输效率 |
| 流量 / 带宽限制 | 客户端级限流（需在 `nps.conf` 开启对应开关） |
| 端口白名单 | `allow_ports` 限制可开放端口范围 |
| IP 访问限制 | `ip_limit` + 客户端 register / Web 登录自动注册 IP |
| 连接数 / 隧道数限制 | 防止滥用与恶意长连接 |
| 端口复用 | `bridge`、HTTP/HTTPS、Web 可复用同一端口 |
| Web 防爆破 | 同一 IP 连续登录失败超过 10 次，约 1 分钟内禁止重试 |

---

## 5. 管理与运维能力

- **Web 图形化管理**：客户端、TCP/UDP 隧道、域名、流量与带宽统计等
- **多用户模式**：可开启用户登录/注册（`allow_user_login` 等）
- **Web API**：便于自动化对接（详见 `docs/webapi.md`、`docs/api.md`）
- **热更新**：Web 中多数配置修改即时生效
- **系统服务**：支持 install / start / stop / restart / uninstall，可注册开机自启
- **健康检查**：配置文件模式下支持 HTTP/TCP 健康检查，失败自动摘除目标
- **环境变量渲染**：npc 支持用环境变量注入 `server_addr`、`vkey` 等
- **日志与 pprof**：可配置日志级别与性能分析端口

## 6. 本仓库修改版增强（重点）

相对原版 `nps` / `npc`，修改版 `nps2` / `npc2` 主要增加以下能力：

### 6.1 长短参数格式

参数由原版 `-server` 风格改为 **长/短参数并存**（基于 pflag），例如：

```text
--server / -s
--vkey   / -k
--config / -c
--type   / -t
--cmd    / -x
```

查看全部参数：`npc2.exe -h` 或 `nps2.exe -h`。

### 6.2 文件尾部追加命令行（单文件启动）

可将启动参数追加到可执行文件末尾，实现「拷贝即用、无需额外配置文件」：

```bash
# Linux / macOS
echo 'CMDLINE: --server 公网IP:8024 --vkey 你的密钥' >> npc2

# Windows（CMD）
echo CMDLINE: --server 公网IP:8024 --vkey 你的密钥>> npc2.exe
```

无参数直接运行可执行文件时，程序会从文件尾部读取 `CMDLINE:` 或 `CRYPTCMD:` 并解析启动。

> **注意：** 必须使用追加（`>>`），不要用覆盖（`>`）。

### 6.3 命令行参数加密

```bash
# 加密一段参数
./nps2 --encryptcmd "--server xxx:8024 --vkey zzzz"
# 或
./npc2 --encryptcmd "--server xxx:8024 --vkey zzzz"

# 客户端使用加密参数启动
./npc2 --cmd <加密后的字符串>
```

也可将加密内容写入文件尾部：

```bash
echo 'CMDLINE: --cmd <加密串>' >> npc2
# 或
echo 'CRYPTCMD: <加密串>' >> npc2
```

适合批量分发客户端、避免明文密钥出现在命令行与脚本中。

## 7. 两种客户端工作模式

| 模式 | 启动方式 | 配置位置 | 适用场景 |
|------|----------|----------|----------|
| 无配置文件 | `--server` + `--vkey`（或文件尾部固化） | 全部在 Web 管理 | 快速部署、统一运维 |
| 配置文件 | `--config npc.conf` | 客户端本地 + Web 可管 | 复杂隧道、健康检查、文件模式 |

配置文件模式下，也可使用服务端 `public_vkey` 进行鉴权。

## 9. 适用与限制提示

- 适合：内网服务临时/长期穿透、演示环境、运维远程接入、多站点域名代理。
- 注意：将 SSH、数据库等高风险端口暴露公网时，务必配合强密码、IP 限制、私密代理或仅内网可达的跳板。
- Windows 下部分杀毒软件可能误报客户端，需加白名单。
- KCP 模式适合专线/高质量网络；丢包较高时请谨慎评估。

更多细节可参阅同目录下的 `example.md`、`feature.md`、`use.md`、`server_config.md`。
