
# NPS修改版

### 0.`cmd/npc2`,`cmd/nps2`为修改版,`cmd/npc`,`cmd/nps`为原版

### 1.参数由`-server`格式改为长短格式`--server/-s`,见`-h`

### 2.命令行参数可追加在文件尾部,实现单文件启动,例如`echo 'CMDLINE: --server xxx:1234 --vkey zzzz'>>npc2`

### 3.命令行参数支持加密,例如`./nps2 --encryptcmd '--server xxx:1234 --vkey zzzz'`, 客户端: `./npc2 --cmd XXXXXXX(加密后的参数)`

### 4.加密后的参数支持追加到文件尾部的方式,例如`echo 'CMDLINE: --cmd XXXX'>>npc2`或`echo 'CRYPTCMD: XXXX'>>npc2`




按照你的环境，下面是完整的落地方案。核心是利用 NPS 修改版的“文件尾部追加”特性，把服务端地址和密钥固化进客户端文件，实现“拷到别的服务器直接用”。

### 📌 环境确认
| 角色 | IP 地址 | 系统 |
| :--- | :--- | :--- |
| NPS 服务端 | 206.119.167.250 | Windows Server |
| NPS 客户端（首台） | 206.119.64.16 | Ubuntu（内网） |

**最终效果**：访问 `206.119.167.250:13306` → 转发到 `206.119.64.16:3306`

---

### 第一步：在 Windows 服务端部署 NPS

**1. 下载并安装服务端**
从 NPS Releases 页面下载 Windows 服务端压缩包（`windows_amd64_server.tar.gz` 或 `.zip`），解压到某个目录，比如 `D:\nps`。

以管理员身份打开 CMD，进入该目录，执行安装：
```cmd
nps.exe install
```
默认会安装到 `C:\Program Files\nps`，配置和日志也都在那里。

**2. 修改配置文件**
用记事本打开 `C:\Program Files\nps\conf\nps.conf`，确认或修改以下关键项：
- `web_port=8080`（Web 管理端口，可改）
- `web_username=admin` / `web_password=123`（**务必改掉默认密码**）
- `bridge_port=8024`（客户端连接端口，记住这个）

保存后，在 CMD 中执行：
```cmd
nps.exe restart
```

**3. 开放 Windows 防火墙**
在“高级安全 Windows Defender 防火墙”的“入站规则”中，**新建规则**，放行 TCP 端口 **8080**（Web 管理）和 **8024**（客户端连接）。如果服务端和客户端之间的流量需要加密，还可能用到 8025，建议一并放行。

**4. 登录 Web 后台创建客户端**
浏览器访问 `http://206.119.167.250:8080`，用 admin / 你设置的密码登录。

进入 **“客户端”** → 点击 **“新增”**，备注随便填（比如 `ubuntu-64-16`）。保存后，你会看到列表中多了一个客户端，**记下它的 vkey（密钥）**，这是后面客户端连接用的。

---

### 第二步：在 Ubuntu 客户端上准备“单文件”客户端

**1. 下载修改版客户端**
你需要的是支持“文件尾部追加参数”的修改版，比如 `qokelate/nps` 或 `ixxxk/nps` 等 fork 版本。从它们的 Releases 中下载 Linux 客户端压缩包，解压得到 `npc` 可执行文件。

**2. 用命令行固化服务端地址和密钥**
假设把 `npc` 放在 `/opt/npc` 下，执行以下命令，把服务端 IP、端口和你的 vkey **追加**到文件末尾：
```bash
cd /opt/npc
# 先赋予执行权限
chmod +x npc
# 把连接参数追加到文件尾部（注意 CMDLINE: 前缀和空格）
echo 'CMDLINE: --server 206.119.167.250:8024 --vkey 你的vkey' >> npc
```
**关键点**：这里用的是 `>>`（追加），不是 `>`（覆盖）。`>` 会把原文件清空，必须用 `>>`。

执行完后，可以 `tail -c 200 npc` 看一下文件末尾，确认参数已写入。

**3. 启动客户端并验证**
```bash
./npc
```
如果连接成功，回到 Web 后台的“客户端”列表，会看到该客户端状态变为 **“在线”**。

为了让它在后台运行，可以用：
```bash
nohup ./npc > /dev/null 2>&1 &
```
或者把它注册成系统服务（参考 `./npc install` 的用法，但固化参数后直接 `install` 可能行为不一致，建议先测试直接运行）。

---

### 第三步：在 Web 后台配置端口转发（隧道）

**1. 创建 TCP 隧道**
在 Web 后台进入 **“TCP 隧道”** → **“新增”**：
- **客户端**：选择你刚创建的 `ubuntu-64-16`
- **服务器端口**：填 `13306`
- **目标 (IP:端口)**：填 `127.0.0.1:3306`（因为隧道是在客户端本机执行的，`127.0.0.1` 指的就是 206.119.64.16 这台机器）

保存后，隧道会自动生效。

**2. 测试连接**
从任意能访问公网 `206.119.167.250` 的机器上，用 MySQL 客户端连接：
```bash
mysql -h 206.119.167.250 -P 13306 -u 用户名 -p
```
如果能连上，说明整个链路已经通了。

---

### 第四步：后续内网服务器复用这个客户端文件

这是你需求中最关键的一点。因为参数已经固化在 `npc` 文件里了，所以**后续其他内网服务器只需要拷贝这个文件，直接运行即可**。

**操作步骤**：
1. 把已经追加过参数的 `/opt/npc` 文件（可以改个名，比如 `npc-64-16`）**拷贝**到其他内网服务器上。
2. 在新服务器上执行 `chmod +x npc-64-16`。
3. 直接运行 `./npc-64-16`。

**但这里有一个重要前提**：这些“其他内网服务器”需要和 206.119.64.16 处在**同一个内网环境**，或者至少能访问到 206.119.64.16。因为隧道配置里写的是 `127.0.0.1:3306`，意味着**所有运行这个客户端文件的机器，都会把“本机的 3306”转发出去**。

**如果你的真实意图是**：在其他内网服务器上运行这个客户端，然后公网访问 `206.119.167.250:13306` 时，**实际连接的是 206.119.64.16 的 3306**（而不是新服务器自己的 3306），那么你需要调整隧道配置。

**更合理的做法**：在 Web 后台再新建一个 TCP 隧道，目标填 `206.119.64.16:3306`（而不是 `127.0.0.1:3306`），服务器端口仍用 `13306`。这样，任何运行该客户端的机器，都会把流量转发到 206.119.64.16 的 3306，与客户端本机无关。

---

### ⚠️ 重要提醒

1. **“文件尾部追加”的兼容性**：这个特性只存在于 **NPS 修改版** 中，官方原版 `ehang-io/nps` 的客户端**不支持**。请务必确认你下载的是 `qokelate/nps` 等修改版的 `npc` 二进制文件。
2. **杀毒软件误报**：NPS 客户端常被 Windows Defender 或火绒误报为恶意软件。如果服务端在 Windows 上被杀软拦截，需要添加信任或临时关闭防护。
3. **如果“拷过去直接用”失败**：先检查新服务器能否 `ping` 通 `206.119.167.250`，以及服务端防火墙 8024 端口是否放行。如果客户端启动后 Web 后台不显示“在线”，通常是网络不通或 vkey 错误。
